The Execution Loop: TurnEngine

Inside `cogniwork/engine.py`, the TurnEngine drives iterative problem-solving with atomic concurrency, live streaming, and graceful error handling.

What is actually happening?

Unlike single-shot LLM APIs, the CogniOS engine loops continuously until the model signals that the user's objective is fully achieved or requests clarification.

  • Asynchronous Concurrency: Non-blocking tool execution using Python's asyncio.to_thread worker pool.
  • Atomic Turn Locking: manager.try_mark_running(session_id) prevents conversation corruption.
  • Mid-Stream Interruption: Cancelling drops in-flight token streams and terminates child shell processes immediately.
  • Automatic Compaction: Triggers at 80% context window capacity to condense older history without modifying canonical JSONL logs.

Security Architecture

Giving AI access to your computer requires a boundary.

CogniOS enforces multi-layered permission models, origin validation, and sandbox constraints.

DISCUSS
Read-Only Analysis

All modifying tools (writes, shell, mutations) are strictly blocked.

PLAN
Architectural Planning

Agent can read code and formulate plans; proposes plan via interactive card.

INTERACTIVE
Default Safe Operation

Reads execute automatically; file writes and shell commands prompt user approval.

AUTO
Full Autonomy

Tools execute within mounted workspace roots without manual prompts.

Defensive Guardrails

  • Loopback CSWSH Protection: Strict Origin checking (`tauri://localhost`, `127.0.0.1`) rejecting rogue web origins with HTTP 1008.
  • Per-Launch Sidecar Token: 64-character random token (`X-CogniOS-Token`) injected into webview headers.
  • Multi-Root Filesystem Sandbox: Canonical path resolution (`resolve()`) blocks directory traversal (`../`).
  • SSRF Address Guard: DNS pinning blocks requests to loopback, RFC1918 private IPs, and AWS metadata IP `169.254.169.254`.
  • Single-Owner Local Auth: Passwords hashed with Argon2id; TOTP secrets encrypted with Fernet symmetric keys.

Architectural Reference

Technical Deep Dive

Detailed breakdown of core subsystems, file structures, and data flows.

⚙️ TurnEngine & Async Loop Mechanics

▼

File: cogniwork/engine.py:TurnEngine

Maintains `self.messages` containing canonical OpenAI-formatted turn history. The `_loop()` method evaluates tool calls in a loop up to `max_iterations`. Low-risk tools run in parallel via `asyncio.gather`; high-risk tools execute serially. Mid-stream interruption is handled by triggering `request_interrupt()` which sets `self._cancel` and terminates child processes via `executor.interrupt_now`.

🛡️ PermissionEngine & Multi-Root Sandbox

▼

File: cogniwork/permissions.py:PermissionEngine & cogniwork/roots.py:RootDir

Enforces 4 operational modes. Every filesystem operation resolves target paths against configured `RootDir` instances. Path traversal escapes (`../`) are intercepted and denied. Operations outside mounted roots require dynamic user elevation via `request_directory`.

🌐 Multi-Provider Routing & Prompt Caching

▼

File: cogniwork/providers/router.py:ProviderRouter

Routes model requests based on prefix. Implements native Anthropic prompt caching (`cache_control`), OpenAI Responses API, Google GenAI SDK, AWS Bedrock, GCP Vertex AI, and local Ollama. Capabilities (vision, pdf, tools, reasoning) are dynamically inspected per model.

🎙️ Native Offline Speech-to-Text

▼

File: stt/src/lib.rs:Dictation

CPAL captures microphone audio at 16,000 Hz mono into an in-memory sample buffer. On stop, `whisper_rs` runs local inference against the quantized `ggml-large-v3-turbo-q5_0.bin` model. Provides real-time RMS input metering for UI waveforms.
