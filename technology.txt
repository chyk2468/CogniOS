1. PROJECT OVERVIEW
--------------------------------------------------------------------------------
* Project Name:
  - CogniOS (Product / Desktop Operating Environment)
  - CogniWork (Backend Agent Platform & Turn Engine Runtime; Python package name: `cogniwork`)
  - CogniOS Action Flow / System Space (`cognios-action-flow` interactive web visualization)

* Project Purpose:
  CogniOS is a local-first AI operating environment and AI coworker agent system.
  Unlike conventional chat bots, CogniOS is designed to deliver finished, concrete
  work—creating and editing files, managing Git repositories, executing terminal
  commands, searching the web, transcribing speech offline with Moonshine Tiny,
  integrating with 34+ external SaaS platforms (Slack, GitHub, Jira, Notion, Linear,
  HubSpot, etc.), scheduling automations via self-wake tools, maintaining persistent
  memory across global and workspace scopes, and executing multi-iteration agent loops
  with granular permission and approval gates. All computation, secrets, and data
  remain on the user's local machine, interacting only with user-configured model
  providers and connected services.

* Architecture Type:
  - Hybrid Desktop Client / Local Agent Server Architecture (Local-First Sidecar Pattern)
  - Frontend Layer:
    * React 18 single-page application with custom Liquid Glass design system, bundled with Vite.
    * Desktop Shell: Tauri 2.0 (Rust) hosting the webview and supervising the local Python server sidecar.
    * Interactive Visualization Layer: `cognios-action-flow` built on TanStack Start, React 19, and Nitro.
  - Backend Server Layer:
    * FastAPI + Uvicorn asynchronous REST API and WebSocket server listening on `127.0.0.1:8765`.
    * Authentication & session control via sidecar token (`X-CogniOS-Token`) and SQLite user session cookies (`ow_session`).
    * Terminal UI alternative: `cognios` CLI powered by Textual.
  - Core Agent Engine Layer:
    * `TurnEngine` in `cogniwork/engine.py` orchestrating multi-turn tool loops with `PermissionEngine`.
    * Provider-agnostic LLM client built on `aisuite` alongside native SDKs (OpenAI, Anthropic, Google GenAI, Bedrock, Vertex).
    * Algorithmic Context Compaction Engine managing token budgets dynamically.
    * Persistent SQLite Memory Store with keyword and workspace/global scoping.
    * Offline Speech-to-Text (STT) powered by Useful Sensors Moonshine Tiny via PyTorch & Transformers (plus `ocw-stt` Rust crate).

  - Moonshine Tiny (Useful Sensors):
    * Model Architecture: `MoonshineForConditionalGeneration` (Encoder-Decoder transformer).

    * Unified multi-provider chat completion, tool definition, and tool-calling library.

    * `explore` tool spawning isolated child agent execution environments for research.

* Context & Memory Management (RAG & Compaction):
  - Algorithmic Context Compaction (`cogniwork/compaction.py`):
    * Dynamic token budget calculation and automatic context shrinking when approaching context limits.
    * LLM-driven structured summarization.
    * Mechanical preservation of recent user messages and tool states while shedding voluminous stale tool results.
  - Scoped Persistent Memory Store (`cogniwork/memory/`):
    * SQLite-backed persistent memory facts (`remember`, `memory_read`, `memory_update`, `memory_forget`).
    * Scoped by `global` (user-wide) or `workspace` (project-wide).
    * Automatic injection of relevant memory items into system prompt context before turn execution.
  - Multimodal Document Support (`cogniwork/pdf_support.py`):
    * Pure-Python PDF text extraction via `pypdf>=5`.
    * PDF page rasterization and rendering via `pypdfium2>=4` (BSD PDFium engine) for models lacking native PDF support.

8. DATABASES AND STORAGE
--------------------------------------------------------------------------------
* SQLite 3:
  - SQLite is the primary, embedded local relational database engine used for all persistent
    application state.
  - File Location: `{state_dir}/cogniwork.db` (Default on Windows: `%APPDATA%\cogniwork\cogniwork.db`;
    on macOS/Linux: `~/.config/cogniwork/cogniwork.db`).
  - Database Schema & Tables:
    * `memories` — Stores persistent agent memory facts with fields `id`, `scope` (`global` vs `workspace`),
      `key`, `content`, `summary`, `workspace`, `session_id`, `created_at`.
    * `sessions` — Registry of conversation sessions, titles, models, timestamps.
    * `workspaces` — Registry of authorized workspace root directories and project trust settings.
    * `users` — Local single-owner account table with `full_name`, `username`, `email`, `password_hash`,
      `favorite_pet_answer_hash`, `totp_enabled`, `totp_secret_encrypted`.
    * `auth_sessions` — Active user sessions with `id`, `user_id`, `expires_at`, `last_activity`.
    * `auth_recovery_tokens` — Secure state tokens for password reset flow.
    * `auth_pending_logins` — Temporary tokens during two-step 2FA sign-in.
    * `auth_totp_setup` — Temporary tokens during 2FA enrollment.
    * `audit_events` — Audit logs capturing all agent actions, tool executions, and system events.
    * `inbox_items` — Parked user approval requests for unattended agent runs.
    * `channel_subscriptions` — Event listeners and recurring scheduled automations.

* Alembic / SQLAlchemy:
  - Used for database schema migration documentation and headless migrations (`alembic.ini`,
    `alembic/env.py`, `alembic/versions/edb11258dadb_create_auth_tables.py`).

* JSONL (JSON Lines) File Storage:
  - File Location: `{state_dir}/conversations/{session_id}.jsonl`.
  - Append-only persistent storage of full conversation turns, user inputs, assistant outputs,
    tool call definitions, tool results, and thought logs.

* Structured File Storage:
  - `{state_dir}/secrets.json` — Local JSON secret store (filesystem permissions `0600`) holding
    encrypted model API keys and third-party connector tokens.
  - `{state_dir}/memory-settings.json` — User configuration for memory injection and rules.
  - `{state_dir}/sidecar-{port}.token` — Per-launch transient secret token for FastAPI sidecar auth.
  - `{workspace}/.cogniwork/config.toml` — Workspace-level agent configuration overrides.
  - `{state_dir}/config.toml` — Global agent configuration.

* SafeTensors Binary Storage:
  - `stt/moonshine-tiny/model.safetensors` — 108 MB binary weights for the Moonshine Tiny STT model.

13. CONFIGURATION AND ENVIRONMENT
--------------------------------------------------------------------------------
* State Directory Resolution:
  - Windows: `%APPDATA%\cogniwork` (falls back to legacy `%APPDATA%\coworker`).
  - macOS / Linux: `~/.config/cogniwork` (falls back to legacy `~/.config/coworker`).
  - Override Variable: `COGNIWORK_STATE_DIR` (legacy: `COWORKER_STATE_DIR`).

* Configuration Files:
  - Global Configuration: `{state_dir}/config.toml`
  - Workspace Configuration: `{workspace}/.cogniwork/config.toml`
  - Key Configuration Options:
    * `model` — Default model ID (e.g. `gpt-5.5`, `claude-fable-5`, `gemini-3.6-flash`).
    * `mode` — Default permission mode (`plan`, `interactive`, `auto`, `custom`, `discuss`).
    * `max_iterations` — Maximum model<->tool iterations per turn (default: 12).
    * `allowed_commands` — Command prefixes auto-approved without user prompt (e.g. `ls`, `git status`, `pytest`).
    * `auto_allow` — List of tool names auto-approved in `custom` mode.
    * `host` — Server bind address (default: `127.0.0.1`).
    * `port` — Server port (default: `8765`).

* Verified Runtime Environment Variables (Names only — No secret values):

14. ARCHITECTURE / TECHNOLOGY FLOW
--------------------------------------------------------------------------------
The complete system interaction flow operates as follows:

1. User Interaction:
   - The user launches the CogniOS desktop app (Tauri shell wrapping a React 18 frontend).
   - Voice Input (optional): Microphone audio is captured via Rust `cpal` in `ocw-stt`, processed by PyTorch & Transformers running Moonshine Tiny, and converted into text transcripts instantly and offline.
   - Text Input: The user submits a prompt via the Composer interface.

2. Transport & Authentication Layer:
   - React UI sends a WebSocket message (`user_message`) over `ws://127.0.0.1:8765/ws/session/{id}`.
   - FastAPI server (`cogniwork/server/app.py`) validates the per-launch `X-CogniOS-Token` and optional `ow_session` cookie.

3. Session Management & Engine Initialization:
   - `SessionManager` (`cogniwork/server/manager.py`) resolves the active session, acquires the session turn lock (`claim_turn`), and invokes `TurnEngine.run()` (`cogniwork/engine.py`).

4. Context Preparation & Memory Retrieval:
   - `agent.py` queries `SQLiteMemoryStore` (`cogniwork/memory/`) for durable facts matching global and workspace scopes.
   - Relevant memories, active persona instructions (`cogniwork/personas/`), workspace directory trees, and loaded skills are injected into the system prompt.
   - If previous history exceeds token thresholds, `compaction.py` algorithmically summarizes older turns and compacts context.

5. Model Inference:
   - `TurnEngine` calls `ProviderRouter` (`cogniwork/providers/router.py`), selecting the requested model client (OpenAI, Anthropic, Gemini, Bedrock, Vertex, or OpenAI-compatible endpoint).
   - The provider streams response tokens and tool call proposals back to `TurnEngine`.

6. Permission & Tool Execution Loop:
   - If the model requests tool calls (e.g. `write_file`, `run_shell`, `web_search`, `mcp__*`, connector calls):
     * `PermissionEngine` (`cogniwork/permissions.py`) evaluates the tool risk against current mode (`discuss`, `plan`, `interactive`, `auto`, `custom`).
     * If user approval is required, a `PERMISSION_REQUIRED` event is pushed over WebSocket to the UI (or parked in `inbox_items` SQLite table if unattended).
     * Upon user approval, `TurnEngine` executes tools (concurrently for read operations, sequentially for write operations).
     * Tool results are appended to the conversation history.
   - The loop repeats until the model finishes or reaches `max_iterations`.

7. Persistence & Event Emission:
   - Full conversation events, tool executions, and tokens are written to `{state_dir}/conversations/{session_id}.jsonl`.
   - Session metadata is updated in `cogniwork.db`.
   - Real-time `TURN_END` event is broadcast to the UI to finalize the transcript view.

Summary Pipeline:
`Voice (CPAL/Moonshine) / Text (React) → WebSocket / REST → FastAPI Server → TurnEngine → SQLite Memory Store → aisuite / Native LLM SDKs → Model API → PermissionEngine → Tool Execution (Files/Shell/MCP/Connectors) → SQLite & JSONL Storage → Real-time UI Transcript`
